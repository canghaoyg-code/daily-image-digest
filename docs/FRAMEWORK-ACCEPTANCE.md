# 框架改造验收 · 2026-09-17

范围：按用户要求先完成编辑生产框架，不采编或发布新一期，不改历史内容，不以换样式代替流程修复。

| 原有断点 | 实现 | 验证 |
| --- | --- | --- |
| RSS 候选直接拼成一期，热榜发现未接入 | 工作台导入实际观察、候选和渠道限制；仅 RSS 无法进入验收 | 单元测试 + 真实导入命令 |
| 先选容易读取的文章，再补选题理由 | 议题关联发现证据、候选、材料任务和最终条目；逐项输出缺口 | 来源或条目跳过选材会失败 |
| 重点难采集就悄悄消失 | 重点 held 阻止发布；舍弃须说明，验收再次审视 omissions | 缺材料及重点遗漏测试 |
| 同样转述语气和来源集中不被看见 | 工作台显示来源分布、引语/转述数量，提示编辑套话；不以固定配额自动批准 | 指标只用于复核，不冒充内容质量评分 |
| 手写 approved 就算通过 | 四项成品观察、桌面/手机检查、待解决问题和重点取舍共同组成验收 | 只有批准字段、缺移动端、问题未解决均失败 |
| 内容已变，继续沿用旧验收 | 批准绑定正文、来源、选题、本地图片字节和当次渲染代码 | 改正文、图片或渲染使批准失效；补尺寸/发布状态不失效 |
| 发布器与日常执行规则脱节 | 新草稿初始化工作台；发布命令与 CI 都执行检查；自动更新已接入 import/status/review/seal | 合成样本完整走命令链；既有任务保持 PAUSED |

## 实际执行结果

- 19 项 Node 测试、7 项 Python 采集测试、4 项静态页面测试通过，共 30 项；内容/图片检查、lint、类型检查及生产构建通过。
- 端到端测试在临时隔离目录构造明确标注的合成样本，实际执行创建、导入、返工、批准和入库命令。缺材料、仅写 approved、批准后修改标题均拒绝发布，目录未改变；合格合成样本完成入库与再次校验。
- 测试样本没有写入真实 content/editions；此次没有新建或改写真实期号。线上最新期仍应为 2026-09-13 晚间版，框架提交不能让它显示为今天。
- 保留浏览器登录会话的使用约定，不保存密码或凭据；不向旧 Sites 站点发布。

## 仍由实际编辑负责

程序可以检验流程关联、时效和批准是否失效，不能证明观点有独立价值、短引忠实、图像值得看或整期好读；也不能阻止编辑有意伪造记录。这些须在下次真实出刊时用原文和正式页面检验。

与参考图卦的差距因此不能仅凭这些测试宣称消失。本轮完成的是可执行的框架及其阻断验证，不是“已经达到参考网页编辑质量”的结论。下一期应特别看国内公共议题的原声、图片本身的信息、篇幅主次与自然收尾，而不是再按数字凑条目。
