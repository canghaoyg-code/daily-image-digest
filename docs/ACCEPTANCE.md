# 成品验收：先读页面，再谈通过

本表用于实际编辑验收，不是新的内容配额。不能仅因文字中写了“已审查”就视为通过。用本期具体条目、源页和实际屏幕观察作证，填写既有 editorialReview，并在交付时如实说明结果。

## 真实性底线

- 以本次系统北京时间为当天。逐条依据原页时间计算当天、前一天、更早数量；当天至少70%。旧内容明确标背景、回顾或长期阅读；不可用抓取时间或页面模板日期替代首发日。
- 每段说法对应可辨认发布者和原文。短引忠实；省略不改变原意；译摘有标识。观点不被写成本站确认的事实。互动量只记实际可见值及观察时间。
- 不绕过登录、付费墙、私密内容、反爬与安全提示。无权限的渠道记为受限，未看的记未观察。发现线索不算已经读完原帖。
- 图片有原始出处、语境、替代文字，遵守具体引用与许可边界。不复制喷嚏图片、整篇长文截图、无关资料图。实际有效图常规16—20张或覆盖约70%条目，按独立图而非重复放置计算；图片目标不能凌驾于日期真实性。
- 保留历史期号。无广告、无打赏；只发布指定 GitHub Pages。正式发布仍须构建、部署、本轮SHA和线上期号全部一致。

## 四个编辑问题

| 问题 | 看什么证据 | 需要返工的表现 |
| --- | --- | --- |
| 读到了不同人的声音吗？ | 直接发言、采访、独立解释与反对意见；作者身份和语气清楚 | 全部由编辑转述；“他开了个玩笑”代替那个笑话；给所有观点写统一结论 |
| 图片本身提供了什么？ | 能读懂的原始现场、图表、产品差异、作品细节或短帖片段 | 只有人物头像、机构Logo和气氛图；坏图仍算入密度；图中文字手机上不可辨认 |
| 整期有重点与跨度吗？ | 重要热点得到充分展开，短讯快速带过；公共生活与国际材料不是象征性补位 | 条条同样长；照格式轮流填空；大半一期来自同一容易采集的入口 |
| 读完留下了什么？ | 有记忆点的具体图像、表达或信息；轻读收尾自然成立 | 抽象标题和编辑升华比原材料更多；只是缩写过的门户目录 |

任一核心问题仍明显失败，报告为“未达编辑标准”，不要把技术通过包装为完成。

`editorialReview.decision` 默认为 `revise`（返工）。完成上述实际复核后才可设置为 `approved`；发布器会拒绝缺少决定或仍在返工的草稿。这个决定是编辑责任记录，不是自动打分；说明文字非空不代表通过。

## 实际页面检查

使用正式数据和正式渲染器预览，不再另写一份与生产无关的HTML来替代实现。检查开篇、中段、重点组和结尾；桌面及手机都看。

- 短讯在屏幕上确实紧凑，图片条目不被多余文字盖住，重点组允许展开；不能只统计 format 字段。
- 逐图实际加载与解码，读图注，确认图文对应；外链HEAD成功不等于页面可显示。
- 原声先让读者认出谁在说话，再读短引或译摘。多个观点不得因来自同一主题被过滤掉。
- 目录、原文、同题阅读、图片出处与页内锚点可操作；手机无溢出，图片不裁掉关键部分。
- 核查非故意的来源重复、图片重复、上一期重复和对单一领域的过度集中。
